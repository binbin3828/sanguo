# 大地图战场与手机镜头：修订设计（评审稿）

> 2026-09-29。此前 [17 号设计稿](17-战场地图与手机界面全面设计.md) 提议将战场缩为 10×9，用户指出格子数过少。本稿**撤销该尺寸决定**；旧稿的七张 10×9 字符图不作为制图依据。地图与镜头的首轮实现已接入游戏，后续平衡和逐城美术仍按本稿推进。

## 1. 核心结论

**完整战场采用原版规模 32×32，共 1024 格；手机屏幕只显示其中一块，镜头可横向和纵向移动。** 完整地图、屏幕视口、缩略图是三个不同概念：

| 层次 | 建议尺寸 | 用途 |
|---|---|---|
| 逻辑战场 | 32×32，固定世界坐标 | 地形、单位位置、寻路、射程、天气、存档；与原版资源尺寸一致 |
| 手机战术视口 | 依屏幕而定，约 10–12 列 × 11–15 行 | 看清格子、点选、行军；镜头拖动，不能代表全图 |
| 全图缩略图 | 约 72×72px，按 32×32 压缩 | 观察敌我、城池和道路方位；点击或拖动缩略图跳转镜头 |

依据：`Fight.c:FgtLoadMap` 从资源 110–116 加载 7 张 32×32 地图；`config.c` 默认屏幕是 208×128 像素，`baye/fight.h` 的 `SCR_MAPWID = SCR_WID/16`、`SCR_MAPHGT = SCR_HGT/16 - 1`，所以原版默认一次显示 **13×7 格**，通过 `FgtGetMapDat` 与焦点移动查看其余区域。原版也没有要求 1024 格一次塞进屏幕。[原版地图图集](assets/classic-battle-maps.png)、[46 个原始图块](assets/classic-battle-tiles.png)、[可读取的原地图数据](../data/classic-battle-maps.json) 已导出；来源为 [iBaye 源码](https://gitee.com/bgwp/iBaye)。

当前项目 `BattleCore.js` 实际只有 10×8（80 格）。以步兵每回合约走 4 格计，当前地图从出发到城池只需短短几步，无法形成原版的远近路线、侦察推进、夺桥和围城阶段。32×32 下，边缘到中心城约 12–16 格，按地形消耗通常是 3–6 个行动回合；这才有调兵和转向的空间。回合上限、粮草与单位数量要随地图规模重新平衡，不能把小图数值原封不动搬过去。

## 2. 手机镜头与触控

### 2.1 视口计算

战场格的显示尺寸目标 **30–36 CSS px**，像素画按最近邻放大。镜头显示的列/行由可用宽高除以格宽求得；保持方格，不为了塞全图挤压格子。

| 示例设备 | 可见格数目标 | 地图交互 |
|---|---|---|
| 320×568 竖屏 | 约 10×11～12 格 | 镜头拖动；选中单位后可立即居中 |
| 390×844 竖屏 | 约 11～12×14～15 格 | 可看到更大的战术局部 |
| 横屏手机 | 约 16～20×8～11 格 | 左侧战场，右侧情报与指令 |

视口必须同时满足 `visibleCols ≤ 32`、`visibleRows ≤ 32`；窄屏或安全区较大时减少可见行数，操作区仍固定。地图容器使用 `touch-action: none`，由同一套指针/触摸逻辑处理双轴位移；手指横移和竖移都更新镜头偏移。手势移动超过约 8px 判定为拖动，松手不触发格子点选。镜头偏移限制在地图边界内，允许轻微弹性回弹但不露出空白。

镜头默认聚焦当前可操作部队或布阵区；点选武将、敌方攻击关键目标、回合开始与夺城事件时可“定位”，**玩家正在手动拖图时不抢镜头**。屏幕边缘提供短暂拖动提示；点“定位我军 / 定位城池”可快速返回。普通行动不强制镜头跟着动画跑，避免眩晕。横屏和竖屏记录同一个世界坐标焦点，旋转屏幕后重新裁切视口。

### 2.2 缩略图和全图查看

右上角 72×72px 缩略图常驻但可收起：地形只显示大色块和山水轮廓；城池金色标记、我军青点、敌军红点、当前镜头白框。缩略图不承载单格点击精度；点一个区域只是把镜头中心移动过去。点缩略图的扩大按钮打开**全图态势层**，可看 32×32 全景、双方位置、路线和城池目标，再点区域返回近景操作。全图态势层不可直接下攻击指令，以免误点。

玩家点战场上的格子后先显示单位/地形与可执行动作，再由底部大按钮确认。地图格只有 30–36px，不能假装满足 44px 触控按钮标准：选格后在手指上方显示放大浮签、路线和坐标，允许改选；底部主要操作按钮至少 44px 高。双击可定位/聚焦，长按查看详情；缩放可作为辅助，但**拖动、缩略图跳转和定位按钮**必须在默认倍率下就能完成全部战斗。

### 2.3 一个屏幕的固定框架

```text
┌ 晋阳攻城  第 3/30 回合  ☔雨  [全图] ┐
│ 我军 2870   敌军 1940   粮 7        │  固定顶部：目标、回合、天气、态势
├───────────────────────────────────┤
│  看见的是 32×32 中的一块             │
│  格子约 30–36px；可上下左右拖动     │  战术视口尽量占满剩余空间
│                         [缩略图]  │
│  [选中单位] ── 路线 ── [目标]       │
├───────────────────────────────────┤
│ 赵云  骑兵 980  HP72  MP18 [详情]   │  紧凑武将/目标卡
│ [移动] [攻击] [计谋] [待机]          │  当前行动对应的大按钮
│ [定位我军] [定位城池] [结束回合]    │  固定底栏，含安全区
└───────────────────────────────────┘
```

选择攻击或技能时，镜头允许继续拖动；合法目标的标记保留在世界坐标上。目标在屏幕外时，视口边缘显示方向箭头与距离，而不是让玩家猜目标在哪里。地图上方不能铺大段文字；技能列表、地形详情、战斗日志用抽屉覆盖，关闭后回到原世界坐标。

## 3. 地图制作：保留原版规模，重做城市辨识

### 3.1 基础与图层

首批直接把原版 7 张 32×32 图的地形编号读成结构化地图，用它们作为**地貌参考底图**；不把旧编号误称为“平原图、关隘图”等原版名称。原始 16×16 图块可以用于内部对照；正式发布的新版图块建议重绘为逻辑 32px 画幅，像素边缘清晰。公共数据分层：

1. `terrain[32][32]`：平原、草地、山地、森林、村庄、城池、营寨、河流，唯一基础地形。
2. `fixture[]`：桥、浅滩、城门、寨门、官道、码头、城墙；决定额外通行与关卡节点。
3. `decoration[]`：城墙屋顶、水田、芦苇、岩石、城徽等，只改变外观，不暗改碰撞。
4. `dynamic[]`：雨、火、水淹、烟雾、技能范围和行动状态，随回合变化。

一个 `C` 仍是规则上的城池核心，但视觉可向邻格外溢成有体量的城楼。山脉按山脊连续绘制，森林按林带聚集，河流从一侧边界贯穿或进入湖泊；避免“随机撒几个障碍格”的现版观感。桥是 `river + bridge`，必须有明确两岸；原版部分河流图块看似桥面，C 逻辑仍按河流算，不能只看图案赋予陆军通行能力。城市外观包括城墙颜色、地方建筑、旗帜、周边农田或雪线，但每格规则清楚可读。

### 3.2 七类 32×32 战场的空间布置

下面坐标以左上角 `(0,0)`、右下角 `(31,31)` 描述**新版的制图约束**；它们是可制作的坐标方案，不冒称原版七张图的精确位置。默认城池核心在地图中心约 `(14～17,14～18)`，保留每张原图实际中心偏差。攻方按来路从对应地图边缘 0～3 格深处布阵，守方在城池周围及外围节点。所有模板都保留至少两条独立的陆路，进城最后 6 格也不能被一队兵完全封死。

| 模板 | 32×32 地形摆放草案 | 争夺节点与城市气质 |
|---|---|---|
| **北方开阔战场** | 中央 `x=8～23,y=7～24` 以平原/草地为主；森林两片置于西北 `(4～9,3～10)` 和东南 `(23～29,22～29)`；村庄沿 `y≈9`、`y≈24` 两条道路 | 中路骑兵快、两翼树林掩护弓兵；北平用寒草甸、邺用田垄、许昌用官道 |
| **西北关隘** | 山脊沿 `x≈10～14`、`x≈23～27` 成带，给北口 `y=7～10` 与南口 `y=21～24` 两处通道；谷地通向中心城，水道不横切全部通路 | 两路围关，外围营寨设在其中一处山口；西凉沙色、汉中谷地、云南湿热山林 |
| **荆南林谷** | 森林集中在 `x=4～12,y=3～11` 及 `x=19～29,y=21～30`，沿中央保留宽 2～3 格道路；村庄置于岔路与林缘 | 伏击、远程遮挡与村落支线；襄平偏冷，武陵/零陵/桂阳偏湿润 |
| **大河争桥** | 贯穿南北的河带 `x=11～14`；北桥设 `y=8～10`，南桥设 `y=22～24`，两桥间距足以形成绕行；城池在东岸中心，村庄和营寨分守两桥 | 陆军争桥、水军沿河机动；襄阳突出大河与城门，柴桑突出江岸营垒 |
| **江淮水网** | 主河 `x≈9～12`，支流由 `(10,7)` 向 `(22,20)` 斜走；至少两座桥或一桥一浅滩，水面总量建议 20%～35%，城池周围留陆地环道 | 三角洲中的主路、渡口、村落形成多目标；建业有外郭，庐江有支流 |
| **海港登陆** | 一侧边界为海面，水域建议 30%～45%；靠海陆地至少两块上岸区，每块宽 3～5 格；城池在内陆中心，码头/栈桥连至上岸区 | 陆军从沙洲或码头合法格出生，水军在海面机动；吴、会稽的水路来袭使用，陆路来袭改用水网/林谷变体 |
| **都城纵深** | 中心城外围设置两道不完整防线：外营半径约 9～12 格，城门/护城河半径约 3～5 格；北门、南门至少两处入口，城周有回旋空间 | 先拔营寨再夺城；洛阳宫城、长安关门、成都近城河，守军有纵深但不能无限堵门 |

地貌面积、山河连续性、桥位和入口需要依据原始底图逐张重绘，不对 32×32 原图做简单拉伸/裁剪。**原版 5 号图约 94% 为河流**，若原样用于普通陆军攻城就近乎不可玩；仅可保留为特殊水战/海岛战的参考，常规吴、会稽战场重绘为有合法陆路的海港图。

### 3.3 来路、距离和单位密度

原版 `FgtGetBaseXY` 根据北、东北、东、东南、南、西南、西、西北八个方向选择进攻边缘位置。新版地图也使用战略地图的源城→目标城方向确定边缘部署区，**不把所有攻方固定在左边**。八方向均有 3～6 个合法布阵格，斜向从角部展开；若部署格落在河流或山崖，则找同边最近的合法地形并保持队形。守军在城核心、外营和交通节点分层布阵，不堆到一个 3×3 方阵。

32×32 若只有 1～3 队，会显得空旷。地图首版将出征上限提高到 **5 名武将**，守方可有 4 名武将加一支守城军；这仍低于原版的最高单位规模。可用任务点和推进提示避免玩家在空图里盲找敌军：初始标明城池方位和已知营寨，未侦察敌军可在缩略图上隐藏具体位置。进军 2～4 回合遇到第一道争夺节点，随后围城；这个节奏需与回合上限一起校准。

## 4. 38 城与地图母版

旧版 7 张原始地图是考据资源，**新版城市归类按地貌与攻城路线重新安排**：

| 母版 | 城市 | 同母版的个性化重点 |
|---|---|---|
| 北方开阔 | 北平、南皮、邺、平原、濮阳、许昌、小沛 | 草甸、官道、村落密度不同 |
| 西北关隘 | 西凉、安定、天水、晋阳、河内、汉中、梓潼、棉竹、巴郡、云南、建宁 | 山脊走向、谷地湿度、关口营寨不同 |
| 荆南林谷 | 襄平、武陵、零陵、桂阳 | 林带方向与草甸/湿地比例不同 |
| 大河争桥 | 徐州、下邳、寿春、襄阳、江夏、柴桑、长沙 | 河宽、桥位、城门与江岸营垒不同 |
| 江淮水网 | 北海、庐江、建业 | 海岸/支流/外郭不同 |
| 海港登陆 | 吴、会稽 | 水路进攻时启用海港；陆路进攻切换为水网或林谷变体 |
| 都城纵深 | 洛阳、长安、宛城、成都 | 城墙、外营、护城河的层数与样式不同 |

同城同来路的基础地形固定，不在每次战斗随机重排。季节/天气只改变图层和规则状态。城池建筑等级可以增加营寨或强化城门，但不能封死所有路；存档记录母版版本和地图种子，保证读档后地形不跳变。城市特征的准确性可以在正式制图时再逐城审阅；目前该表先锁定战略主题。

## 5. 制作与实现顺序

1. **地图数据层**：保持原版 7 张 32×32 地图档案只读，建立新版 `BattleMap` 32×32 数据结构；地形、设施、装饰、动态效果分开。移动/攻击/技能都使用世界坐标。
2. **镜头和缩略图**：先以原始 32×32 资源做交互样机，实现双轴拖动、点格、缩略图跳转、单位/城池定位、横竖屏适配。手机上先把“能走遍整图且能准确点格”做出来。
3. **逐图制图**：先做晋阳关隘、襄阳争桥、洛阳纵深、吴城海港四张，确认山、水、桥与陆军通行；再补其余母版与 38 城装饰/变体。
4. **战斗规则适配**：调整部署、单位数、AI 长途寻路、目标情报、回合上限、粮草消耗；小图的伤害与行动数不直接沿用。
5. **手机指令界面**：固定顶栏、战术视口、紧凑单位卡、底部大按钮；抽屉承载技能详情，结果反馈仍在当前镜头上出现。

地图可用性的验收场景：在晋阳从任意合法方向出征，能通过缩略图找到城池、双向拖图、移动至山口；在襄阳争两桥，陆军不会穿水；在吴城海港，陆军部署格和到城路线合法；在 320px 宽手机上，无需网页上下滑动即可完成点选、预览、确认、结束回合。**整张 32×32 不要求在战术倍率下一屏看全**；全图态势层负责全局判断，近景镜头负责操作。

## 待评审决定

我建议先锁定 **32×32 战场 + 手机局部镜头 + 缩略图/全图态势层**。这既沿用原版的空间尺度，也给手机手指留下可操作的格子尺寸。城市母版与每座城的地标可以在镜头交互样机完成后逐张评审。
