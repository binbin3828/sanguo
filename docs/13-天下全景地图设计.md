# 天下全景地图设计

当前已实现全景坐标、动态道路、节点与标签、势力着色和最近节点选取。最终的密集城群手感与低高度手机排版仍需真机体验后微调。

## 目标与边界

- 手机竖屏的战略主画面一次显示全部 38 城及其地理关系，不放大、不拖动地图，也不滚动页面。
- 地图承担「看天下形势、选城」两件事。选中城市后，城池卡片和指令入口在原位更新；复杂资料仍从详情抽屉打开。
- 调整地图坐标和路线画法，不在这一步修改哪些城可互相出征。`CITY_ROUTES` 同时是行军邻接规则，改动它会改变玩法，需要单独设计。

## 屏幕布局

保留顶部剧本与月份、底部指令和结束本月。地图在两者之间使用剩余高度，任何手机尺寸都完整展示全图。地图本身用百分比坐标随容器伸展，不再使用固定 `620×455` 像素画布。

## 地图形状与城池

1. 将现有横向长图重排为适合竖屏的紧凑疆域：西北、河北、中原、巴蜀、荆楚、江东、岭南六个视觉区域。城市的相对方位保留，例如西凉在长安西北、洛阳在中原、建业在江东、成都在西南。东西两端收拢，密集的徐州、下邳、建业、吴、会稽一带错列摆放，避免节点重叠。
2. 38 座城始终有可见节点。节点用小城池印记呈现，不用大按钮铺满画布。主画面常显约 8–10 个地标城名，如北平、邺、长安、洛阳、汉中、成都、襄阳、建业、长沙；当前选中城和其相邻城显示完整名称。其余城点击后在固定城池卡片显示名称和归属。这样全景不会被 38 个标签盖住。
3. 玩家城用亮金描边和双环，其他势力按君主分配稳定颜色，无主城为空心节点。选中城有持续光环，相邻城加浅色外圈；颜色之外保留形状差异，避免只靠色彩判断。
4. 在小屏（以宽 320、高 568 CSS 像素为基线）保持节点最小间距。地图空白处触摸时按屏幕坐标选取最近节点，并设置距离上限；近邻节点由最近距离决定，避免透明点击区互相盖住。底部「选城」抽屉始终是精确选城的备用入口。

## 路线与背景

- 视觉语言改为「像素军略沙盘」：深色绢地图面、克制的山脉与河道纹理、城池方印、木色道路和选中时的金色光圈。区域名像地图题字，资源数字留在城池卡片，不散落在地图上。地图边框与底部命令区保持同一套像素边饰，避免像网页里的独立图表。
- 原有行军邻接关系保留。所有路线以细、低对比度的道路显示；当前城通往相邻城的路线提亮，并在终点标出可出征的敌城。地图上不出现箭头墙或大块说明文字。
- 路线用轻微弯曲和层次错开处理交叉，跨区域长线更淡；不能因为视觉弯曲让路线看上去连接到错误城池。河流与山岭画成几笔低对比度底纹，为地形提供方向感，不盖住道路和节点。
- 对地图的所有权变化只更新节点颜色和路线状态；不绘制大面积随局势频繁变化的领土色块，避免遮挡城池。

## 交互反馈

点城池后立即更新城池卡片，地图上的该城和相邻道路高亮；短按只负责选城。要看完整资料点卡片「详情」，要下令点固定的四类指令。行军合法性仍由现有相邻城规则决定，视觉路线和规则必须一致。月末天下纪事播放结束后，地图直接显示新归属，并在本月易主城短暂显示标记。

## 实施顺序

1. 在 `MapData.js` 增加仅用于全景渲染的新坐标；保留 `CITY_ROUTES` 邻接数据。
2. 用响应式全景组件替换 `620×455` 的可滚动画布，移除地图滚动位置与自动聚焦逻辑。
3. 实现节点与路线的选中态、势力色、地标标签和最近节点选取。
4. 调整不同屏幕高度下的地图区域和底部卡片，确保 320×568 与常见 390 像素宽竖屏可完整显示。
5. 用实际手机检查最密集城群的误点、文字遮挡、横竖屏切换和安全区；根据结果微调坐标。

## 完成标准

- 进入任何剧本时，38 城节点与整张路线网一次可见；地图没有横向或纵向滚动。
- 点选每座城都能正确更新卡片；密集城群可通过最近节点选择，且「选城」抽屉始终可用。
- 易主后的颜色、当前城相邻路线、可出征目标和实际行军规则一致。
