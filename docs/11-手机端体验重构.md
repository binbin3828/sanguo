# 手机端游戏主画面设计

## 交互目标

战略阶段固定在一屏内，不再通过纵向滚动页面寻找城池资料、政令和出征入口。地图一次显示全部 38 城，无需拖动或放大；长列表只在弹出的抽屉内部滚动。手机浏览器安全区留给底部操作栏。

## 信息层级

1. **主画面**：顶部显示势力、剧本和月份；中部是地图；地图下方只保留当前城池的归属、兵力、金、粮、后备兵与可接令武将数；底部固定四类指令、军情与结束本月。
2. **选择城池**：点地图城市或「选城」抽屉。我方城池使用中央主楼较高的浅暖金色三塔城楼 SVG 加红旗，配深棕描边与门窗，图标略大，旗杆插入主楼，城名以浅暖金色常驻显示；敌方使用低矮城墙加固定蓝旗，旗杆连接城墙；城墙保留势力颜色，无主城使用灰色城楼，不显示旗子或旗杆。选中城池以白色细圆环标记，不再持续闪烁我方光圈。选城后更新当前城池卡片，并高亮该城与相邻道路。城池详情抽屉展示完整指标、武将和本月命令。
3. **选择指令**：内政、人事、军备、外交分别打开指令抽屉。暂不可执行的项目置灰，并在项目下方直接显示具体原因：「金币不足」「本月已接令」「体力不足」「农业已满」「无合适目标」等短语；同时存在多个限制时，仅显示首个主要原因。选将列表、道具操作和确认按钮也显示原因；调整交易或携带物资时，确认按钮的原因同步更新。非己方城池在四类指令上方显示归属限制。
4. **完成指令**：一般政令为「指令 → 选武将 → 确认 → 即时回报」。出征先选目标城，再选将并填写携带金粮，面板实时显示耗粮、可供回合数和城中保留库存；招降增加俘虏选择；分配兵力为「选武将 → 调整兵数 → 确认」；确认后直接返回原有的「选择分配武将」列表，更新兵力并以轻提示显示分配结果，可继续选择下一人；不弹出分配回报，也不返回战略主画面。取消选将时返回上一级目标或指令列表。寻访、招降结果与天下大事在月末居中弹窗中逐件播报，不使用事件列表。

## 当前实现范围

主画面及抽屉已经接通开垦、招商、治理、出巡、寻访、招降、征兵、分配、出征；军情、存档和月末结算也从固定入口打开。外交已接通离间、招揽、策反太守和劝降势力；人事已接通移动、宴请、俘虏处置及道具赏赐与没收。全景地图不滚动，指令抽屉可以局部滚动，战略主页面本身固定在手机视口内。

## 选将推荐顺序

选将列表先分为「本月可接令」和「本月不可接令」，后一组保留在底部并写明已行动、体力不足或未带兵等原因；推荐只改变默认展示和批量执行顺序，不替玩家自动选择武将。

| 指令 | 当前规则对应的推荐依据 |
| --- | --- |
| 开垦、招商 | 当前开发公式随智力提高，按智力从高到低。 |
| 寻访 | 找到人才的判定及资源收益与智力有关，按智力从高到低。 |
| 招降 | 根据执行者智力、俘虏智力和忠诚计算当前简化成功率，按成功率再按智力排序。 |
| 出征 | 按当前战斗规则的带兵数与预计攻击综合排序；无兵武将不可选。 |
| 治理、出巡、征兵 | 当前收益不受执行者属性影响，优先安排武力和智力均不突出的武将，把专精武将留给其他任务。 |

同档次武将再按剩余体力、固定武将 ID 排序，使列表在反复打开时稳定。批量下令按照推荐顺序执行，尤其避免临近城市属性上限时由较弱武将先占用资源。推荐依据以后会随规则模型更新。

## 后续工作

真机检查较短屏幕、浏览器地址栏变化和密集城池误点；继续补移动、输送、侦察等规则。发布微信小游戏前还需适配运行环境与触控反馈。
